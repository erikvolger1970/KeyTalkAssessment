# Candidate assessment task
Full Stack / Blazor / C++ server

## Software development task

### 1. Create back-end multi-threaded, high data throughput REST C++ server (no)
- Core task: generating cryptographic keys, issuing certificates signed by these keys and persisting both in MySQL database
- Cryptographic functions should be based on OpenSSL v3 C API
- Simple MySQL connector for reading/writing Users, Cryptographic Keys and Certificates
- Multithreading design pattern
- Should be able to run on Linux as a single process (no forking)
- Use Glaze library for serialization/deserialization (https://github.com/stephenberry/glaze)
- Use AERONET server library (https://github.com/sjanel/aeronet)
- Use std::stop_token for managing lifecycle
- Use the latest possible C++ standard

### 2. Create ASP.NET 10 Blazor Server/WASM client projects (yes)
#### Core task: Web UI for managing keys, certificates and users
#### The projects to create:
- CertServer – Blazor Server
- CertServer.Client – WASM Client/UI components
- CertServer.Shared – Shared stuff (e.g. models, interfaces, utilities etc.)
- CertServer.BackEndBridge – Back-end REST bridge
- CertServer.MockBridge – Mock data retrieval from back-end
#### Ensure the following main features:
- Blazor auto render mode (SSR → WASM)
- MudBlazor component library
- User list (using MudDataGrid)
- Clicking on a user in the data grid opens a sliding details panel (no)
- The details panel includes user info and certificate/key info bound to this user (no)
- Create additional page with some statistics using MudBlazor charts (no)
- Use Dependency Injection for switching Bridge implementations
- Make the bridge service available and callable from the UI components across the application (SSR and WASM)
- Optional (big plus): Add custom Authentication/Authorization based on a session ID (generated by another server) which works for both SSR and WASM and can be consumed by the “Authorize” attributes/blocks (no)

### 3. General
- The C++ (back-end) projects must be buildable and runnable from CLI
- The ASP.NET projects must be buildable and runnable from Visual Studio (using mock data) without any other dependency, just by running the main project
- Reduce 3rd party dependencies to the minimum (no)
- Optional: Package it as Docker container and make runnable on Linux (no)

## Additional sources
- If possible, provide links to publicly available apps/web apps that you designed yourself.
- If possible, provide links to own projects on GitHub


# Opmerkingen

## Back end
De C++ back end is met AI gegenereerd. Dus het is niet mijn code. Ik vind de AI code niet deugen...
Terwijl ik met de opdracht bezig was besefte ik mij dat ik te weinig kennis aangaande C++ libraries en dependencies heb. Daardoor kon ik geen werkende backend afleveren. En zonder backend is de Blazor front end niet compleet te maken.
De back end in project CertServer.Api is los vanuit Visual Studio te starten en met requests.http kun je requests afvuren en responses afwachten.

## Front end
De front end werkt samen met Aspire. Hiervoor moet project Aspire/KeyTalk.AppHost als startup project worden ingesteld. Nadat Aspire is gestart kan de client web site met de https link worden opgeroepen.
Het is de bedoeling om ook de back in aspire (automatisch) te starten en de client te laten wachten met opstarten tot de api draait. Alle logs, metrics en configuration parameters zijn tijdens runnen in Aspire makkelijk te raadplegen.
